# 近距离表面覆盖验证

用户报告：漫游靠近物体或墙面时，表面变透明。

## 原因与修改

原渲染器始终把每个高斯的投影半径限制为 32 像素。相机靠近后，真实投影会增大，但这个限制会把已有表面压缩为分离的点，露出背后的内容。

固定测试墙面由 441 个高斯组成，单点中心不透明度为 0.99。相机正对墙面，距离从 1 改为 0.1，近裁剪面保持 0.02。相机没有穿过墙面。
旧设置在近处产生明显空隙。仅把投影半径上限增大到 512 后，空隙消失。没有修改模型、不透明度、模糊参数或裁剪面。

修改后，场景内保留覆盖物理像素视口对角线的投影上限。相机到场景中心的距离从 1.2 倍场景半径增加到 2.4 倍时，上限平滑减小到原有的 32。
键盘移动、平移、旋转、滚轮缩放、场景尺度和视口尺寸变化都会更新这个值。

## 实际像素检查

使用当前 Chrome 和项目内置 Spark 渲染器生成截图，再用 Pillow 检查每个测试视口中央的 80×80 像素。截图坐标已核对。暗像素定义为 RGB 三个通道的最大值小于 50（8 位值）。
指标只描述这个固定测试场景，不能作为真实房间的重建质量分数。

- 旧设置：远处归一化红通道均值 0.92048，近处 0.09322。近处暗像素占比 84.671875%。
- 修复后：远处归一化红通道均值 0.92058，近处 0.91895。两个采样区域的暗像素占比均为 0。
- 旧设置的覆盖回归按预期失败。修复后，同一检查通过。

复现截图及像素记录位于 `runs/near-surface-20261026/`。`red.png` 和 `green.png` 都使用左列旧设置、右列对比设置；下排为近处。
检查命令：


完整命令 `tools/workbench/test_assistance_all.ps1 -Native` 通过 Node 101 项和 Python 105 项，无跳过。
日志位于 `runs/near-surface-20261026/regression/`。本地服务已提供新的查看器和渲染模块。

额外通过 Chrome 的实际输入事件核对了键盘后退和滚轮拉远，两者均把上限更新为 32。复位后，扩大视口会重新计算覆盖范围。
例如 800×600 视口、像素密度约 1.35 时，近距离上限更新为约 1350。记录保存在 `movement-receipt.json`。

参数语义参考 [SparkRenderer 官方文档](https://sparkjs.dev/docs/spark-renderer/)。实现使用本项目内置版本，没有升级或替换渲染依赖。

首先使用 IMG_2394 对应的相机位置，检查空调、墙面和床头。原设置出现明显透明和重影，新设置显示出连续的墙面和床头。
