# GaussRoom 高斯房间

GaussRoom 是在 Windows 上运行的室内三维重建工作台。它使用照片或 iPhone LiDAR 扫描数据，调用 COLMAP 和 Brush，生成可以在浏览器中漫游的高斯场景。

项目提供四种数据入口：

- **电脑照片**：选择本机照片文件夹，运行重建。
- **房屋视频**：选择本机视频文件，或在手机网页上传；工作台自动抽帧后与照片一起重建（两类素材可混合）。
- **手机照片网页**：iPhone 使用 Safari，安卓使用 Chrome。通过局域网上传照片，再由电脑重建。此方式无需安装 APP，也无需 Mac。
- **iPhone LiDAR APP**：使用原生 APP 采集彩色网格和标定关键帧。网格可离线查看；高斯场景仍由电脑训练。APP 源码已提供，构建和设备验收需要 Mac。

本文档在原有文档基础上更新了手机网页自动采集功能。核对日期为 2026-11-04。功能已有实现不代表已经通过手机实机验收。

## 功能概览

- 串行执行素材预处理、特征提取、特征匹配、稀疏重建、几何门禁、去畸变和高斯训练。
- 支持上传房屋视频：按走动速度自动抽帧，过滤模糊、过曝与近重复画面，缓存可跨重建尝试复用。
- 支持增量式和全局式照片重建，支持标准和增强特征档位。
- 几何连接不足时等待用户补充。支持对应点、区域范围、局部位置修正和资料复用。
- 使用独立重建尝试保存日志、数据库和模型。失败时保留历史模型。
- 分别显示几何连接、区域覆盖、画面检查、实际尺度和训练目标状态。
- 显示累计执行时间和各阶段时间。等待人工操作的时间不计入执行时间。
- 支持电脑键鼠和手机触控漫游，支持高斯 PLY 下载。
- 手机网页支持逐张上传、失败重试、批次恢复和项目删除。照片默认预览 6 张，展开后每页 12 张。
- 手机网页支持定时采集、本地待传缓存和电脑估计的拍摄位置图。连续取景需要手机信任局域网 HTTPS 证书。

照片及扫描数据在本机处理。桌面源照片只读。手机照片会复制到项目内。首次准备 Python 环境和外部工具需要下载依赖；准备完成后，常规重建不依赖云端推理服务。

## 环境准备

### Windows 工作台

准备以下组件：

- Windows 和可用的图形驱动。当前启动脚本和默认路径面向 Windows。
- Node.js 20.12 或更新版本，建议使用 Node.js 22。项目使用 Node 内置模块，不需要 `npm install`。
- uv 和 Python 3.13。Python 版本见 [.python-version](.python-version)，依赖见 [pyproject.toml](pyproject.toml) 和 [uv.lock](uv.lock)。
- COLMAP 4.2.1。默认使用 CUDA 版本；选择 CPU 特征处理时使用单独配置的 CPU 版本。
- Brush 0.3.0，以及能运行该构建的 GPU 和驱动。COLMAP 的 CPU 选项不等于 Brush 已支持纯 CPU 训练。
- ffmpeg 与 ffprobe。手机 HEIC/HEIF 上传与全部视频输入都依赖它们；视频需要完整发行包（含 `zscale`/`tonemap`，用于把手机 HDR 转成 SDR）。只用 JPEG 且不处理视频时可以留空。

外部工具二进制不在 Git 仓库内。将匹配版本解压到以下位置，或在 `.env` 中配置其他路径：

```text
tools/colmap-4.2.1-cuda/bin/colmap.exe
tools/colmap-4.2.1/bin/colmap.exe
tools/brush-0.3.0/brush_app.exe
```

获取工具时使用 [COLMAP 官方发行页](https://github.com/colmap/colmap/releases) 和 [Brush 官方发行页](https://github.com/ArthurBrussee/brush/releases)。不要直接用其他版本覆盖现有工具；命令参数和输出格式可能变化。

项目未规定一个经过验证的最低显存容量。所需内存、显存和训练时间取决于照片数量、分辨率、场景及档位。

### 安装与启动

在仓库根目录打开 PowerShell：

```powershell
uv sync --locked
if (-not (Test-Path -LiteralPath .env)) { Copy-Item -LiteralPath .env.example -Destination .env }
node tools/workbench/server.mjs
```

配置复制仅在 `.env` 不存在时执行。已有配置应直接编辑，勿覆盖。

也可双击 [start.bat](start.bat)。浏览器默认打开 `http://127.0.0.1:8123/`。端口被占用时，服务会尝试下一个端口；以终端显示的地址为准。批处理中的提示地址是默认值。

检查工作台顶部的工具状态。缺少依赖时先修复环境，再启动重建。关闭启动窗口或按 `Ctrl+C` 会停止服务；手机查看器随后无法读取电脑结果。

### 配置项

[.env.example](.env.example) 提供以下配置：

- `PORT`：桌面监听端口，默认 `8123`。
- `WORKBENCH_PYTHON`：Python 路径，默认 `.venv/Scripts/python.exe`。
- `COLMAP_GPU`：CUDA 版 COLMAP 路径。
- `COLMAP_CPU`：CPU 版 COLMAP 路径。
- `BRUSH`：Brush 程序路径。
- `FFMPEG`：ffmpeg 路径；同目录需有 `ffprobe`（找不到时会再查 `PATH`）。视频与 HEIC 需要它。

相对路径按仓库根目录解析。系统环境变量优先于 `.env`。配置不需要云服务密钥。`.env` 不提交到 Git。

桌面服务只监听回环地址。手机使用独立网关，默认端口为 `8124`，默认关闭。`PORT` 不控制手机网关端口。接口边界见[代码设计](docs/CODE_DESIGN.md#http-api)。

## 视频重建

1. 用手机横屏或竖屏**边走边拍**，速度接近正常人步行；转角和门口放慢，避免快速甩镜头。
2. 单段建议 10 秒到 8 分钟、1080p 以上。多房间可以分几段拍摄，但相邻两段要拍到同一面墙或同一个门口。
3. 在工作台点击「新建项目」，在「房屋视频」里选择视频（可多选），需要时再补一个图片文件夹。
4. 「每段视频保留帧数」保持自动即可：工作台按时长取 40–300 帧。帧数越多覆盖越全，但匹配耗时约按帧数平方增长。
5. 点击「开始重建」。抽帧发生在「素材预处理」阶段，日志会显示每段视频的保留帧数。
6. 完成画面检查时，留意抽帧报告里的告警：模糊、纹理不足、视角过少、画面亮度跳变都会单独提示。

视频不会被复制进项目，抽帧结果缓存在 `projects/<id>/video-frames/`。同一段视频重跑预处理不会重新解码。手机端视频上限为单段 1 GB、每批 6 段，并会核对时长（3 秒至 10 分钟）与长边（≥1280）后才允许提交。

iPhone 默认用 HEVC 录制。若提示无法解码，把「设置 → 相机 → 格式」改为「兼容性最佳」后重录，或用 ffmpeg 转成 H.264 MP4：

```text
ffmpeg -i input.mov -c:v libx264 -crf 20 -pix_fmt yuv420p -c:a aac output.mp4
```

## 电脑照片重建

1. 拍摄连续、有重叠的照片。进入相邻房间时，拍到门框、墙角或固定家具等共同内容。
2. 将原图保存在独立文件夹。当前文件夹入口读取该目录直接包含的图片，不递归导入子文件夹。
3. 在工作台点击“新建项目”。填写名称，选择图片目录和训练档位。
4. 保留默认相机模型 `SIMPLE_RADIAL` 和增量式重建；只有明确知道原因时才更改。
5. 点击“开始重建”。工作台创建工作副本，并依次执行七个阶段。
6. 若显示“等待用户补充”，按问题添加照片或标记对应点。保存回答后，再点击“继续求解”。
7. 几何检查通过后，继续去畸变和训练。场景导出后可在页面打开或下载。
8. 完成画面检查。检查门口连接、重影、比例和区域覆盖。

至少两张照片只是输入下限，不能保证重建成功。大面积白墙、镜面、重复地砖、运动物体和重叠不足都会降低成功率。未拍摄的表面不能通过增加训练步数恢复。

### 训练档位

- `fast`：10,000 步，最多 500,000 个高斯，球谐阶数 1，每 2,000 步导出。
- `standard`：20,000 步，最多 800,000 个高斯，球谐阶数 2，每 5,000 步导出。
- `full`：30,000 步，最多 1,000,000 个高斯，球谐阶数 2，每 5,000 步导出。

手机默认使用 `standard`。界面中的训练时间和文件体积为估计值，不是硬件性能承诺。特征档位与训练档位是两组选项：标准特征最多 8,192 个 SIFT 特征，增强特征最多 16,384 个，并开启引导匹配。

### 质量和时间

模型导出不等于质量验收完成。普通照片没有可靠实测标定时，实际尺度显示“未实测”或“未验证”。不能直接将模型坐标解释为米。

几何门禁要求注册率至少 80%、平均重投影误差不高于 2 像素、稀疏点至少 5,000 个，并检查真实观察轨迹构成的连通区域。详细判定见[几何门禁](docs/TECHNICAL_GUIDE.md#geometry-gate)。

总耗时累计各阶段的实际执行时间，包括重试。等待人工补充和作业间隔不计时。旧项目没有完整时间记录时会标注不完整，不显示为零。

## iPhone 与安卓照片网页

1. 确认手机和电脑连接同一局域网。
2. 在工作台展开“手机照片重建与 LiDAR 导入”，点击“启用连接”。
3. 用手机打开显示的 `/mobile/` 地址，输入配对码。不要在手机上使用 `127.0.0.1`。
4. 创建批次，填写项目名并选择档位。
5. 点击系统拍照或选择相册。也可按下面的步骤配置 HTTPS，再使用页面内自动采集。
6. 等待逐张上传完成。检查失败项，点击重试或移除。
7. 提交照片创建项目，再点击“开始重建”。提交本身不会启动训练。
8. 查看阶段、进度、累计耗时和质量状态。生成结果后点击“打开模型”。

手机批次至少包含两张 SHA256 不同、可完整解码、长边不少于 1,000 像素的照片。内容去重按文件字节哈希进行；不同编码的近似照片不一定被判为重复。

默认上限为单张 64 MiB、每批 500 张、每批总量 4 GiB。JPEG 和 PNG 可用。HEIC/HEIF 以电脑返回的能力为准。完整参数见[手机照片接口](docs/CODE_DESIGN.md#photo-api)。

刷新后，已上传照片从电脑恢复。系统拍照和相册中未上传的文件需要重新选择。页面内采集的照片先写入 IndexedDB；服务器确认上传后才释放本地 Blob。失败时重传当前整张照片，其他已完成照片保留。

当前批次卡片下方提供“删除批次”或“删除项目”。确认后会删除电脑端该批次及关联项目数据，无法撤销。重建中不能删除。删除失败时修复磁盘权限或文件占用，再点击重试。此入口不负责删除 iPhone 本地 LiDAR 扫描。

### 启用页面内相机

1. 在电脑点击“启用 HTTPS”。首次签发需要数秒。HTTP 默认端口为 8124，HTTPS 默认端口为 8125；桌面仍使用 8123。
2. 通过手机原来的 HTTP 页面下载公开证书。将手机显示的 CA 指纹与电脑显示的指纹核对。
3. iPhone：下载并安装描述文件。进入“设置 → 通用 → 关于本机 → 证书信任设置”，为 GaussRoom CA 启用完全信任。安装入口可能显示在“已下载描述文件”或“VPN 与设备管理”。详见 [Apple 手动证书信任说明](https://support.apple.com/en-ie/102390)。
4. 安卓：下载 `.cer`。在系统安全设置中安装为 CA 证书。具体入口随系统版本变化。回到 Chrome，确认 HTTPS 页面没有证书错误。
5. 在已配对的 HTTP 页面点击切换 HTTPS。页面用短期单次交接码恢复同一设备和当前批次。若交接过期，返回 HTTP 页面重试。长期令牌不放入地址。
6. 在 HTTPS 页面允许后置相机，选择 1、1.5 或 2 秒间隔，点击开始。默认间隔为 1.5 秒。可暂停、继续、停止和手动补拍。

相机请求理想 1920×1080 分辨率，并使用设备实际返回尺寸。自动照片来自预览帧，保存完整画面 JPEG；它不是系统相机的高像素原图。长边不足 1,000 像素时禁止自动采集，可继续使用系统拍照或相册。

自动模式跳过明显模糊、严重曝光异常及高度相似的纹理画面。弱纹理只提示。同一位置转向后可以继续拍。手动补拍可绕过相似画面限制。网页不能保证识别全部重复物理位置；已保存照片不会被自动删除。

页面先保存照片，再逐张上传。断网时保留本地照片并重试上传，采集可继续缓冲。本地待传达到 20 张或 128 MiB 时暂停。切后台、相机中断或存储失败时也暂停。恢复后由用户继续。不要清除浏览器站点数据；该操作会删除本地未传照片。HTTP 与 HTTPS 的本地存储互相隔离；切换前须传完本地照片。

有效照片达到首轮条件后，电脑分批估计相机位置。电脑忙碌时显示等待。地图显示估计位置、朝向及稀疏点，点击相机查看照片。每次更新整图替换；计算与网络会造成延迟。未定位照片单独列出。地图尺度未实测，不能证明表面完整覆盖或几何门禁已通过。详细阈值、状态及接口见[采集与位置分析设计](docs/CODE_DESIGN.md#capture-api)。

没有可信 HTTPS、相机权限或连续取景能力时，页面说明原因并保留系统拍照与相册。证书只在本机生成，私钥不会提供下载。电脑定期检查 IP 和有效期，必要时更新服务器证书；通常无需重新安装 CA。设备令牌可在工作台撤销。只在可信局域网启用网关。

### 在相机画面查看补拍方向

1. 打开网页相机，站稳并把后置镜头对准墙面。
2. 点击“启用方向引导”。若手机请求方向权限，允许后即可显示点阵。
3. 跟随箭头缓慢转动，把空心点移到准星附近。照片成功保存后，对应点变绿。画面模糊、曝光异常或转动过快时，先按提示调整。
4. 在“补拍部位”选择墙面、上方、下方或门口。上方提示关注天花边缘，下方提示关注家具下沿。门口提示分别朝两个房间拍摄，保留共同内容。
5. 走到新位置或门口后，点击“新站位／门口”，重新记录该站位的方向。还需绕到家具后面补拍遮挡处。

点阵是当前站位的**方向示意**，不贴合墙面，也不测量表面覆盖率。点全部变绿不代表房间已经拍全。照片中不会出现点阵或箭头。停止相机、切后台或刷新会重置方向记录，已保存照片继续保留。方向数据过旧或权限不可用时，页面保留文字提示和正常拍照。此功能无需 Mac，也不需要电脑先完成位置分析。细节见[方向引导设计](docs/CODE_DESIGN.md#direction-guidance)。

## iPhone LiDAR APP

源码和工程位于 [apps/ios](apps/ios)。扫描需要带 LiDAR 的 iPhone、iOS 17 或更新版本，并且设备同时支持网格和场景深度接口。

### 在 Mac 上构建

1. 在 Mac 安装带合适 iOS SDK 的 Xcode。Mac 系统要求以 [Apple 的 Xcode 要求](https://developer.apple.com/xcode/system-requirements/)为准。
2. 打开 [GaussRoom.xcodeproj](apps/ios/GaussRoom.xcodeproj)。
3. 选择 `GaussRoom` target。设置开发团队和唯一的 Bundle Identifier。
4. 连接 LiDAR iPhone，选择 `GaussRoom` scheme 并运行。
5. 允许相机和局域网访问。运行 `GaussRoomTests`，再完成扫描实机验收。

工程目标系统为 iOS 17，Swift 语言设置为 5.0。模拟器不能代替 LiDAR 扫描验收。Mac 可先使用以下命令检查工程；本轮 Windows 文档验证没有执行这些命令：

```sh
xcodebuild -list -project apps/ios/GaussRoom.xcodeproj
xcodebuild -showdestinations -project apps/ios/GaussRoom.xcodeproj -scheme GaussRoom
```

在 Xcode 中按实际可用设备选择测试目标。不要照抄不存在的模拟器名称。

### 扫描与导出

1. 开始新扫描，缓慢移动。支持单房间及一次连续扫描中的相邻房间。
2. 暂停后可在同一会话中继续。切后台请求暂停；会话中断或失败会结束扫描。
3. 停止后打开扫描。使用模型视图旋转、平移和缩放。
4. 点选两处估算距离。输入世界坐标最小值和最大值裁剪，使用“撤销裁剪”恢复原范围。
5. 点击“生成彩色模型并导出 OBJ”，导出含 OBJ、MTL 和纹理图片的 ZIP。
6. 至少保存两张不同关键帧后，导出完整 `.gaussroom.zip` 扫描包。
7. 在连接页配对电脑，选择扫描包上传，点击电脑增强并打开在线高斯结果。也可将扫描包复制到电脑后离线导入。

原生 APP 上传入口从文件名读取扫描 ID，并检查本机原始扫描。请保留 `<扫描 UUID>.gaussroom.zip` 文件名，以及 APP 中对应的本地扫描。改名或来自其他手机的包，请使用 Windows 离线导入；有效扫描包不因此被服务器格式判为无效。

裁剪保留原始网格和关键帧，只改变手机网格显示与 OBJ 副本。电脑使用完整原始扫描。裁剪仅保留三个顶点都位于范围内的三角面，不切分边界三角形。

LiDAR 项目不使用普通照片的人工几何修正，也不能追加普通照片。相机位置或连接有误时，请重新扫描并导入新的完整包。

手机测距是估算值。ARKit 米制坐标和深度诊断也不能证明实际测量精度。没有可靠纹理图像的面使用中性色。

当前未交付可安装 IPA。iOS 编译、签名、LiDAR 真机扫描、内存、温度和测量误差仍待验收。

## 漫游操作

- 电脑右键拖动旋转，左键拖动平移，滚轮缩放；`W/A/S/D` 在水平面移动。
- 手机单指旋转，双指平移或捏合缩放；使用屏幕箭头移动。
- “重置视角”恢复初始相机。“切开顶部”与房间范围裁剪只改变查看效果，不修改训练输出。
- 手机在线查看高斯场景时，电脑和网关必须保持运行。原生 APP 的本地网格查看不依赖电脑。

## 故障处理

- **工具未就绪**：核对 `.env` 路径，执行 `uv sync --locked`，检查驱动及工具版本。
- **手机无法连接**：核对局域网、终端端口、网关启用状态和 Windows 防火墙；重新获取过期配对码。
- **照片上传失败**：检查格式、分辨率、容量和磁盘空间；重传当前照片。刷新后重新选择未上传文件。
- **等待用户补充**：查看共同内容和缺失区域。房间标签不能替代真实图像观察。也可将独立区域复制为新项目检查。
- **去畸变数据过期**：从去畸变阶段重跑。不要将旧数据手动拼接到新模型。
- **恢复训练被拒绝**：检查模型、数据和检查点是否匹配。已有更晚导出时，旧检查点不能覆盖它们。
- **重启后项目未完成**：查看保存的日志与中断状态，再重试。服务不保证自动续跑外部进程。
- **网关状态保存失败**：检查磁盘空间和写权限。新版会尝试重建状态目录；不要手动删除正在使用的数据目录。

删除整个电脑项目会删除其内部工作数据和历史结果。桌面项目外部的源照片不随之删除；项目内保存的手机上传副本会删除。删除前应另存需要保留的模型和扫描包。

## 开发与验证

代码主要位于 [tools/workbench](tools/workbench)、[apps/ios](apps/ios) 和 [scripts](scripts)。`scripts` 包含辅助分析工具；产品主流程以 `tools/workbench` 为准。

在仓库根目录运行全部 Node 测试：

```powershell
$testFiles = @(Get-ChildItem -LiteralPath tools/workbench -Filter 'test_*.mjs' | ForEach-Object FullName)
node --test @testFiles
```

运行全部 Python 测试：

```powershell
$env:PYTHONUTF8 = '1'
& .venv/Scripts/python.exe -B -m unittest discover -s tools/workbench/py -p 'test_*.py' -v
```

视频抽帧的黄金测试分两轨：轨 A 用确定性合成帧、不经 ffmpeg，精确钉住选帧结果；轨 B 用四个入库的 H.264 fixture 走真实 ffmpeg 解码，需要 ffmpeg 与 ffprobe（`.env` 的 `FFMPEG` 或 `PATH`）。缺少 ffmpeg 时轨 B 按设计**失败**而不是跳过，也不会改用 OpenCV 静默代跑；干净 checkout 上这些失败属预期行为，与本节末尾「默认跳过的用例不能算作通过」同一口径，不代表套件损坏。

部分原生几何集成测试使用 `GAUSSROOM_NATIVE_TEST=1`，需要 COLMAP 和相应依赖。默认跳过的用例不能算作通过。旧的 `test_assistance_all.ps1` 仅选取部分 Node 测试，不能代替上述全量命令。

本轮检查结果和后续设备验收清单见 [PRD 验证状态](docs/PRD.md#verification)。桌面夹具不替代 iPhone Safari、安卓 Chrome 或 LiDAR 实机验收。
