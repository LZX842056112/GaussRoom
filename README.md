# GaussRoom 高斯房间

从一组照片重建**可漫游的室内三维高斯场景**。本地 Node 服务驱动浏览器界面，串起 COLMAP 稀疏重建与 Brush 高斯泼溅训练，产出可在网页里用 WASD 自由漫游的 `.ply` 场景。

整条链路是自托管的：照片不进任何远端服务，原图只读，工作台只在项目目录里生成长边 2048 的工作副本。

## 快速开始

```bat
:: 1. Python 环境
uv sync --locked

:: 2. 配置（.env 不入库，模板见 .env.example）
copy .env.example .env

:: 3. 启动（也可以双击 start.bat）
node tools\workbench\server.mjs
```

浏览器打开 <http://127.0.0.1:8123/>。页面顶部的工具徽章显示哪些外部工具已就绪；缺哪个就配哪个的 `.env` 路径。

**准备外部工具**：分别把 COLMAP、Brush 解压到 `tools/colmap-4.2.1-cuda/`、`tools/colmap-4.2.1/`、`tools/brush-0.3.0/`。`.gitignore` 已排除这些目录，也排除了下载的 zip/whl 归档。

## 使用流程

1. 左侧 **「+ 新建项目」** → 填项目名称、选图片文件夹、选训练档位与相机模型 → **创建项目**
2. 项目页点 **「开始重建」**，7 个步骤自动串行：

| # | 步骤 | 调用 |
|---|---|---|
| 1 | 照片预处理 | `prepare_project.py`（复制/缩放、分组、写清单，ffmpeg 解 HEIC） |
| 2 | 特征提取 | COLMAP `feature_extractor` |
| 3 | 特征匹配 | COLMAP `exhaustive_matcher` |
| 4 | 稀疏重建 | COLMAP `mapper` / `global_mapper` |
| 5 | 几何门禁 | `gate_model.py`（见下） |
| 6 | 去畸变 | COLMAP `image_undistorter` |
| 7 | 高斯训练 | Brush（中途每 N 步导出 `.ply`） |

3. 训练结束后漫游区自动出现；ESC 或在页面内点「重置视角」回到默认机位。

## 训练档位

| 档位 | 训练步数 | 高斯上限 | SH 阶数 | 参考耗时 | 参考体积 |
|---|---|---|---|---|---|
| `fast` | 10 000 | 50 万 | 1 | 约 20 分钟 | 约 50 MB |
| `standard` | 20 000 | 80 万 | 2 | 约 40 分钟 | 约 100 MB |
| `full` | 30 000 | 100 万 | 2 | 约 60 分钟 | 约 150 MB |

## 相机模型

COLMAP 特征提取的 `--ImageReader.camera_model`，配合 `single_camera_per_folder=1`（同一相机分组的照片共用一套内参）。

| 模型 | 何时用 |
|---|---|
| `SIMPLE_RADIAL`（默认） | 绝大多数情况。参数最少，最不易过拟合，手机/普通相机够用 |
| `OPENCV` | 畸变明显（广角、运动相机、近距离）且照片充足（建议 ≥ 50 张） |
| `RADIAL` | 需要两个径向系数但不要切向项，很少比默认更好 |
| `PINHOLE` | **仅用于已经去畸变的图**（如 ARKit 直出的无畸变图） |

改动相机模型会把 features 及之后所有步骤标记为待运行（内参变了，下游结果作废）。

## 几何门禁

| 阈值 | 值 |
|---|---|
| 注册率 | ≥ 80% |
| 平均重投影误差 | ≤ 2.0 px |
| 稀疏点数 | ≥ 5 000 |
| 碎片份额 | ≤ 5%（多个近似匀速的不连通模型） |

不通过即中止训练。检查会读取最终三维点的观察轨迹，列出每个模型的几何分量、照片数量和照片清单。一个模型文件也可能包含多个没有共享三维点的区域。较大的独立区域按 5% 输入照片阈值判定为分裂；少量孤立照片也会显示，并要求提取连通区域后再训练。

在「验收证据」中点「复制此区域并检查」，工作台会保留源项目，把所选区域复制到新项目，并重新检查。检查通过后，可继续去畸变和训练。独立区域会标注「整体布局未验证」。接口和单步重试都不能跳过几何检查。旧报告在重新检查前显示「几何连接未验证」。

**重建方式**：项目页可切 `incremental`（默认，增量式）／`global`（全局式）。全局式在稀疏重建步骤中先将匹配数据库备份到 `sfm/database-global.db`，运行 `view_graph_calibrator`，再运行 `global_mapper`。校准失败即停止。两种方式都依赖可靠的跨区域匹配，都可能产生独立区域。

**特征档位**：标准档使用最多 8192 个 SIFT 特征。增强档使用最多 16384 个，并开启引导匹配。修改档位后，需要从特征提取重跑。训练继续使用原有 fast／standard／full 档位；所有档位都固定随机种子并保存评估图像，以便比较同一组照片在不同训练步数下的结果。

质量报告会列出跨区域候选照片。候选匹配需要检查真实共同内容，例如门框、墙角和固定家具。相似地砖不能单独证明房间连接正确。缺少可确认的共同内容时，工作台保留当前结果，并等待补充。用户可以另行选择独立区域训练。

## 辅助重建

新建项目会先运行自动重建。工作台会检查最终三维点的共享观察。模型分裂、区域覆盖未知或用户主动要求复查位置时，项目显示“等待用户补充”。此时释放计算作业槽，并阻止整体训练。

1. 在“辅助重建”中查看问题原因和相关照片。选择“是”“不是”或“不知道”。门位关系只是提示，不能证明三维连接。
2. 可以从全部工作照片中手动选图。选择共同物体，圈选共同区域，或标记同一物理位置。平面四角须使用相同顺序；非平面物体使用对应点。标记以已统一方向的工作照片像素保存。
3. 点击“保存回答”。保存不会启动计算。回答会保存在项目根目录的 `assistance.json` 中。重启后可以继续。页面版本冲突时，先保留自己的草稿，再读取服务器版本。
4. 服务器显示信息已就绪后，点击“继续求解”。每条区域连接至少需要 8 个可靠共同点，每侧至少 2 个视角。还要通过视差、重投影误差和点分布检查。若源位姿不可靠，区域合并流程会比较来自匹配数据库副本的增量式区域候选，再执行全局式定位、三角化和联合优化。若首次全局求解丢失可靠连接，流程会保留失败结果，并用已验证的多视角几何初始化一次新的全局求解。它只使用实际照片观察，不能用房间标签代替位置。新结果仍须通过相同的最终检查。
5. 几何连接和目标区域覆盖通过后，继续去畸变与训练。`full` 保持 30000 步、最多 100 万个高斯和 SH 阶数 2。

尺寸是可选项。实测或估计尺寸须关联两个对应点。“不知道”不会阻止几何求解。没有可靠实测尺寸时，实际尺度显示“未验证”。照片没有记录的表面，不能通过增加训练步数恢复。

模型已经连通，但某个区域的位置错误时，可以使用“局部位置修正”。在每张标记照片下选择用途，把该区域的全部照片加入“修正范围”，并选择至少两张位置可靠的“固定参照”。移除标记照片只改变显示，不会移除修正范围。可以在“查看全部范围”中检查和移除范围成员。

可以圈选共同的固定内容，让局部修正自动提取真实图像特征。每张已提交至少 8 个共同点的修正照片，以及每张跨区域圈选照片，都要单独通过初始化和最终检查。旧标记通过，不能代替新增照片通过。自动特征的重复像素只计一次。

同一个共同物体在至少两张修正照片和两张固定参照中有圈选时，可以开始自动特征搜索。圈选只确定搜索区域，不代表连接已通过。客户端只能提交人工标记；自动观察由服务器从照片中提取。

裁剪到局部修正范围后，只有一次观察的点不会进入三维优化。已保存的观察仍保留，后续可以继续补充照片。

连续修正会保留旧模型中已验证的有效观察。只有用户原有标记未改变时，才会沿用该标记的角点细化结果。用户修改或删除的点不会被旧坐标覆盖。替换同一三维点时，还会保留实际共视的范围外观察；用户已否定的照片关系仍会被排除。
多份连接证据包含同一观察时，使用最新已验证的像素。已删除的手工点即使经过角点检测，也不会作为自动点恢复。程序在合并手工轨迹或原生轨迹后，都会重新检查用户否定的照片组合。

局部流程会从匹配副本重新计算选定区域，再使用实际共同点进行联合优化。范围外的相机位置保持固定。所有修正照片都必须有足够且分布合理的有效观察。新结果还要通过跨相机组检查和原有房间连接检查。普通步骤重试和历史来源链会保留这些连接证明。

若两个原生候选各自缺少部分照片，但共同覆盖全部修正照片和参照，流程可以尝试合并候选。合并结果只用于初始化。流程仍须重新检查实际共同点、全部修正照片和原有连接。合并失败时保留失败记录和原有模型。

已定位的照片也可能缺少有效观察。初始化前，每张修正照片和固定参照至少需要保留 8 个三维点观察。流程优先使用观察充足的候选。若合并丢失了观察，会尝试反向合并，并保留两次记录。缓存观察不足时，流程会重新定位，或明确显示缺少可靠初始化。

“高级几何选项”可细化实际图像角点，最大移动为 15 像素。原始人工坐标保持不变，检测结果单独记录。也可用四个已标记边框角点排除镜面内部的自动特征。计算出的区域只用于排除特征，不能作为新增像素观察。旧项目未选择修正范围时，沿用原流程。

“增加照片或复用资料”只在用户明确操作后执行。新增照片复制到项目内，原图保持只读。同内容照片按 SHA 去重；同名异内容使用独立文件名。输入改变后，旧答案保留，但需重跑预处理和后续步骤。只有现有照片时，可以保存该选项。

复用资料前，须选择来源项目、预览并勾选资料。照片改名不影响内容身份。坐标只在工作图片内容、方向和尺寸一致时复用。相机位姿、模型连接结论和已通过状态不能直接复用。

每次重跑使用 `projects/<id>/attempts/<attempt-id>/`。其中保存输入快照、数据库副本、稀疏模型、日志和训练输出。只有新结果通过检查后，才更新 `activeAttemptId`。失败、取消或回答改变时，原模型保留。“查看历史模型”可打开旧导出；历史模型不能代替当前模型提交画面检查。

“模型已生成”不等于完整通过。工作台分别显示几何连接、区域覆盖、画面质量、实际尺度和训练目标。请在“画面检查”中检查门口连接、墙面重影、房间比例及区域覆盖。仍有卫生间重影等问题时，选择“需要改进”。可以勾选“需要重新检查位置”，再补充照片或标记。固定评估对比使用同一评估照片；跨尝试对比只使用内容指纹相同的照片。

辅助接口均位于 `/api/projects/:id/assistance`。GET 读取资料，PUT 使用 `{expectedRevision, patch}` 保存。POST `/run` 使用当前 `expectedRevision` 启动；可选 `untilStep` 为 `gate` 或 `train`。POST `/review` 保存与当前尝试和几何签名绑定的画面检查。旧修订返回 409。客户端不能指定输出目录、数据库路径或已验证状态。

接口新增：`POST /api/projects/:id/components`，请求体为 `{ "model": "0", "component": 0 }`。返回新项目，自动执行区域提取和几何检查，随后等待继续训练。`GET /api/projects/:id/image?name=...` 只提供项目工作图片。项目创建和 PATCH 支持 `featurePreset: "standard" | "enhanced"`，旧项目默认为标准档。

去畸变数据会记录对应的稀疏模型和自身数据签名。直接重试训练时，工作台先检查签名。数据过期或缺失时停止，保留已有训练输出，并提示重新去畸变。

回归检查：`node --test tools/workbench/test_quality.mjs` 和 `python -B -m unittest discover -s tools/workbench/py -p "test_*.py" -v`。

已准备恢复配置的项目可以从检查点继续训练。工作台先检查模型、去畸变数据、训练档位和检查点 SHA256。通过检查后，保留已有导出并追加日志。目录中已有更晚的模型或评估图时，旧检查点不能覆盖它们。重新去畸变会清除恢复配置。训练只有产出目标步数的模型，才会显示完成。

PLY 恢复会载入模型参数，并重新初始化优化器。本次 `room` 的恢复准备脚本位于 `runs/room-quality/prepare_resume.mjs`。它会备份最新完整检查点，并保存中断后的评估图。[Brush v0.3.0 的恢复实现](https://github.com/ArthurBrussee/brush/blob/v0.3.0/crates/brush-process/src/train_stream.rs)。

## 漫游页操作

| 操作 | 效果 |
|---|---|
| 右键拖动 | 360° 旋转：yaw 与 pitch 同时变，左右不夹紧（可转满一圈），上下夹紧在 ±1.5 rad |
| 左键拖动 | 平移：相机与支点一起在屏幕平面内移动，位移随距离缩放（跟手） |
| 滚轮 | 缩放：改相机到支点的距离，范围 `0.1 – maxDistance`（`maxDistance = max(3×场景半径, 20)`，拉到上限即可看见整体模型） |
| <kbd>W</kbd><kbd>A</kbd><kbd>S</kbd><kbd>D</kbd> | 在水平面内移动（固定速度 1.6 模型单位/秒） |
| 重置视角 | yaw / pitch / fov / 距离 / 位置全部复位 |
| 切开顶部 | 用水平面把该高度以上的泼溅变透明，从上方看到房间内部（dollhouse） |
| 只显示房间范围 | 挡掉相机轨迹尺度之外的泼溅（默认开） |
| 切面高度 | 拖动滑块调切割面高度，范围 `home.y ± 0.6×场景尺度` |

相机是**轨道式**：状态为 `target`（支点）+ `yaw` / `pitch` / `distance`。支点放在初始视线前方 2 个模型单位。未实测尺度时，这些单位不能解释为米。拉远后，支点近似场景中心，可绕模型查看。

缩放上限的场景尺度优先取 `?radius=`（工作台按**相机轨迹半径**算：质心到最远相机的距离，本项目实测 7.91 → 上限 23.74）。**不要用高斯点的包围盒**：3DGS 常有远处漂浮点，本项目包围球半径 64、上限会被撑到 192，而房间本体只有 8 左右。`?radius=` 缺失时才退回包围盒，两者都拿不到就用 4。

### 拉远时为什么会「白线糊屏」，以及三个参数

3DGS 训练会产出少数**尺度极大的高斯**。早期 50 万点示例里有 **1,380 个（0.276%）`max(scale) > 2`，最大 221 单位**（房间本体才 16 单位）；离中心 15 单位以外的 490 个漂浮点平均尺度 10.24（是普通点的 170 倍）、平均亮度 0.865（偏白）。Spark 默认 `maxPixelRadius = 512`，单个泼溅最多能画 1024px 直径，几千个叠起来就是整屏白雾 + 放射状白线。相关参数由 `viewer.html` 和 `render-limits.mjs` 控制：

| 参数 | 取值 | 理由 |
|---|---|---|
| `maxPixelRadius` | 近处至少 512，拉远后渐变到 32 | 近处上限覆盖物理像素视口的对角线，避免把墙面高斯压缩成散点。相机距场景中心超过 1.2 倍场景半径后逐渐减小，到 2.4 倍时恢复 32，保留远景的漂浮点限制 |
| `minAlpha` | `≈0.00196 → 0.005` | 兜底剔近全透明点，只丢约 0.3% 的泼溅。**不要靠它治白线**：巨物 alpha 中位数只有 0.022，要剔掉得提到 0.03，那会丢掉 10%+ 的泼溅 |
| 裁剪球（`SplatEditSdf` sphere，`invert`） | 半径 `1.2×场景尺度` | 挡掉轨迹尺度之外的漂浮点。实测到 `home` 的距离 p99.5 = 1.11×尺度，所以 1.2× 只切掉 0.26% |

**不要动** `maxStdDev` / `blurAmount` / `clipXY` / `focalAdjustment`（会改变全局观感）。**`minPixelRadius` 也没用**：`blurAmount = 0.3` 会给每个泼溅的协方差加 0.3，屏幕半径下限被抬到约 1.55px，取 ≤1.55 不生效、取 ≥2 会把拉远后的整个模型剔掉。

近距离限制使用相机的实际位置。键盘移动、平移、旋转、缩放和视口尺寸变化都会更新它。它保留已有表面的投影覆盖，不修改模型透明度，也不能补出缺失的表面。复现、像素对比及限制见 [近距离表面覆盖验证](docs/validation/2026-10-26-near-surface-rendering.md)。

切开顶部与裁剪都用 `SplatEdit`（`splat.edits` 数组，**不挂子节点**——子节点会继承 `basis` 旋转，切割面就歪了）。切割面是 `plane` 型 SDF，`rotation.x = π/2` 让局部 +Z 落到世界 −Y，于是 `distance<0` 恰好是「切面以上」。默认切面高度 `home.y + 0.15×尺度`：实测世界系 Y 的 p95 = `+0.12×尺度`、p99 = `+0.19×尺度`，且**没有明显的天花板平面**（−2.5~−1.0 占 56%，是地板）。**不要用 `splat.getBoundingBox()` 定切面高度**：它返回重建局部系，且被 Y 最高 +47.7 的漂浮点撑大。

默认机位**由重建数据推导**，不是硬编码角度：位置取相机轨迹质心，朝向取轨迹水平主轴并看向较长一端——这样在任意重建里都成立。

## 验收脚本

本轮功能回归和真实 room 结果见 [2026-10-21 验证记录](docs/validation/2026-10-21-assisted-reconstruction.md)。新全局模型已通过强几何检查：297 张照片、一个分量、13 个可靠共享点。它已完成 full 训练。卫生间仍有重影，画面检查未通过。

辅助重建回归使用独立端口和临时项目。运行以下命令。`-Native` 会额外运行真实 COLMAP 校准、全局求解和照片改名检查。

```powershell
powershell -File tools/workbench/test_assistance_all.ps1 -Native
```

正式数据验收使用公共接口。`facts.json` 格式为 `{"version":1,"patch":{...}}`，只允许辅助输入字段。不能包含模型、姿态、数据库或输出路径。`--until gate` 在几何检查后停止；`--until train` 只在几何与覆盖通过后训练。工具会输出新项目 ID，并记录原图指纹和验收结果。可用 `--project-id` 继续指定的验收项目。

```powershell
uv run python tools/workbench/verify_assisted_room.py --base-url http://127.0.0.1:8123 --source-dir C:/photos --facts facts.json --training-preset full --report-dir runs/acceptance --until gate
```

以下旧验收脚本用于原有界面。`verify_api.py` 会修改固定演示项目，不能用于保留实际结果的验收。

```bat
python tools\workbench\check_ui.py      :: 前端元素与后端路由交叉校验
python tools\workbench\verify_api.py     :: 接口验收
node   tools\workbench\verify_ui.mjs     :: 浏览器自动化逐个点击验收
```

`verify_ui.mjs` 从本机 npx 缓存加载 Playwright 驱动 chromium；它需要**仓库内没有带场景的项目时**会跳过漫游相关用例（12 项），其余照常执行。破坏性用例只落在脚本自建自删的临时项目上。

## 已知限制

- **漫游页的 3D 渲染无法在无头环境验证**：headless + 软件渲染下 Spark 的 `splat.initialized` 不完成，渲染循环不启动、截图是空的。鼠标控制靠 `?debug=1` 门控的只读状态钩子断言，画面本身需人工确认。
- 两种重建方式在跨区域约束不足时都可能产生独立区域。增加高斯训练步数不能修复缺失的几何连接。
- 重建吃磁盘（一个 300 张的 full 档项目约 1.8 GB），开始新项目前留意剩余空间。
